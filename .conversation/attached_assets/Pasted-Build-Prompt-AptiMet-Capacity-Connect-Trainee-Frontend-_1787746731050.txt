Build Prompt: "AptiMet" (Capacity Connect) — Trainee Frontend
Project Context
Build the Trainee-facing frontend for a Digital Capacity Building & Learning Management Portal for IMD (India Meteorological Department), part of Smart India Hackathon Problem Statement 26075. This is a frontend-only prototype — use mock/dummy JSON data and local React state instead of a real backend/API.
Platform positioning: This is a competency-mapping and organizational training platform that helps IMD identify skill gaps, match trainees to the right trainers/courses, and track certification — NOT a weather app or disaster-response tool. One feature (Cyclone War Room) is an engaging assessment module within this platform, not the platform's identity.
Tech stack: React (functional components + hooks), Tailwind CSS for styling, react-router for navigation, recharts for charts, lucide-react for icons. Use mock data files (JSON/JS objects) for courses, users, certificates, etc. No real backend calls.
Design tone: Clean, professional, government-platform credible — NOT gamified/childish. Think "modern enterprise LMS" (Coursera for Business / LinkedIn Learning), not a kids' app. Use a calm, trustworthy color palette (blues/teals work well thematically for IMD without being literal weather-themed).
Screens to Build (in this priority order)
PHASE 1 — Core Loop (build fully functional first)
1. Login / Signup


Signup form: name, email, password, role (locked to "Trainee")

On signup submit → show "Pending Admin Approval" confirmation state → redirect to login

Login form → validate against mock user list → redirect to Dashboard

Include basic validation (empty fields, email format) with inline error messages
2. Trainee Dashboard


Widgets: enrolled courses with progress bars, recommended courses, upcoming assessment deadlines, recent announcements/notifications feed

Bell icon (top nav) → notifications dropdown panel

Clicking any course card → Course Detail page

"Browse All Courses" button → Course Catalog

Include an entry card for "🚨 Simulation: Cyclone Response" (links to War Room) — visually distinct but not dominant
3. Profile Page


Sections: personal info, qualifications, work experience, skills (tag chips), certificates (grid with thumbnails)

Edit mode toggle → inline editable fields → Save commits to local state

Clicking a certificate thumbnail → opens certificate preview modal
4. Course Catalog


Grid of course cards: title, trainer name, duration, subject tags, enrolled status

Search bar + filter chips (subject/category, difficulty level)

"Enroll" button on card → optimistic UI update (button becomes "Enrolled", disabled)

Click card → Course Detail page
5. Course Detail Page


Tabs: Overview, Lectures/Materials, Assessment, Feedback

Overview: description, trainer profile snippet, learning outcomes

Lectures tab: list of video/PDF items → click opens modal/embedded viewer (use placeholder video/PDF)

Assessment tab: "Take Assessment" button (disabled unless enrolled) → Quiz screen

Feedback tab: star rating + comment textarea → Submit shows toast confirmation, appends to a mock feedback list
6. Quiz / Assessment Screen


MCQ questions, one at a time or scrollable, options as clickable selectable cards

Progress indicator (Question X of N) + optional countdown timer if deadline-based

Next/Previous navigation, Submit on last question → Results screen
7. Results Screen


Score display, correct/incorrect breakdown, pass/fail badge

Explainable feedback card: Strength / Gap / Recommended module (pull from a mock lookup table mapping wrong-answer-tags → course recommendations)

"View Certificate" button (if passed) → Certificate screen

"Retry" button (if failed) → back to Quiz
8. Certificate Screen


Certificate preview: trainee name, course name, date, mock QR/hash code

"Download" button → trigger a mock PDF download (or just a styled printable view)
PHASE 2 — Differentiator Features
9. Skill-Gap Dashboard


Radar or bar chart (recharts) comparing trainee's current skills vs. target-role required skills (mock data)

Below chart: "Recommended courses to close this gap" — clicking a suggestion pre-filters the Course Catalog
10. Cyclone War Room (Simulation Sandbox)


Full-screen takeover UI: static/animated map (SVG or simple Leaflet-style mock), countdown timer, scrolling event log feed

Scripted JSON timeline of events (e.g., {time: 0, event: "Cyclone forms", requiresDecision: false}, {time: 30, event: "Landfall ETA updated", requiresDecision: true, options: [...]})

At decision points: 3-4 clickable choice buttons appear with a short countdown; selecting one logs the choice and advances the timeline

End screen: Scorecard — decision-by-decision comparison against a pre-defined "expert path," with narrative feedback per decision (e.g., "You delayed the coastal warning by 40 min — here's the modeled impact") and an overall score

Scorecard links back to Skill-Gap Dashboard / recommended module
11. Forecast Duel


Shows a historical weather data snapshot (mock dataset) with data available up to a cutoff point

Trainee submits a forecast via dropdown/slider (e.g., predicted rainfall range, cyclone severity)

On submit → reveal actual historical outcome + the official IMD forecast at the time, side by side, with an accuracy score for the trainee's guess
PHASE 3 — Polish (if time remains)


Notifications panel (if not already built in Phase 1)

Regional/peer leaderboard (filter mock leaderboard data by trainee's region)

Auto-built resume/portfolio PDF (compile profile + certificates into a downloadable view)

Dark mode toggle

Multilingual toggle (English/Hindi) — even static UI string swap is fine for demo
Data Structure Guidance
Create mock data files for:


users.js — trainee profiles (name, email, skills[], experience, certificates[])

courses.js — course list (id, title, trainerName, tags[], lectures[], quiz{})

quizzes.js — questions with options, correct answer, concept tag (for explainable feedback mapping)

scenario.js — the War Room timeline script (events, decision points, options, expert weights, feedback text)

historicalEvents.js — Forecast Duel datasets (snapshot data, actual outcome, official forecast)

notifications.js, leaderboard.js as needed
Keep all data in a /mock-data folder, imported into components — this makes it trivial to swap in real API calls later without restructuring the UI.
Non-negotiables


Every button/card must have a working on-click action (navigation, state change, or modal) — no dead UI elements, since this is being judged live.

Keep the core loop (Phase 1) 100% functional before touching Phase 2 — that's the safety net if time runs out.

Cyclone War Room and Explainable Feedback are the two highest-value differentiators — prioritize them over Phase 3 items.

Responsive layout (at minimum: works cleanly on a laptop screen for the demo; bonus if mobile-responsive).
